# Casquette

Personal Strava training dashboard: Astro 7 (fully static) + content collections. Every ride is a Markdown file with all of its data in the frontmatter (`src/content/rides/`), written by the sync (`npm run sync`). Setup and usage: `README.md` · Sync internals (rate limits, cache/rebuild, legacy time in zones, power and HR backfill, geocoding): `docs/sync.md`.

- Local-only: personal data (rides, gear, streams, `src/data/*.json` except `*.example.json`, `.strava-cache/`) is gitignored and never committed – GPS start/end points reveal home addresses. Without synced rides the site runs entirely on the tracked synthetic `demo/` dataset (`src/lib/data-source.js`). Use demo data for tests, screenshots and docs.
- UI: read `DESIGN.md` before touching it – grey and pink (pink is the default data colour, grey the rest), tokens only, compose from the building blocks listed there, chart colours and shapes from `SERIES`. UI stack decision: `docs/adr/0002-shadcn-recharts-tanstack-table-islands.md`
- UI strings: never hard-code them – keys live in `src/i18n/en.js`, accessed via `t()` / `LOCALE` from `src/i18n/index.js` (language via `PUBLIC_LANG`)
- Everything in the repo is English: docs, code comments, identifiers, CLI output
- Domain terms: `GLOSSARY.md` · Architecture decisions: `docs/adr/` · Feature docs: `docs/ride.md`, `docs/dashboard-period.md`
- The repository is `davidhellmann/casquette`. Its owner/name lives only in `SETUP_URL` (`src/layouts/Base.astro`), the issue tracker line below, `docs/agents/issue-tracker.md` and the `data-repo` elements in `website/index.html` (nav, `#get`, footer) – update all four if it ever moves. Docs link relatively; add no further absolute repo URLs.
- `website/` is a standalone promo one-pager (plain HTML/CSS/JS, no build, not part of the Astro app). Its copy lives in `index.html`; the app i18n rule does not apply there. Its tokens (a copy of the app palette), logo and fonts live in `website/site.css` + `website/fonts/`; browser test: `npm run test:website`. `website/ui/` (real UI fragments of the demo build) is generated by `npm run fragments` – never edit it by hand; re-run it after changing a captured piece (`website/ui/README.md`). `legal-notice.html` and `privacy-policy.html` are templates with `{{SITE_LEGAL_*}}` placeholders, filled at deploy time by `npm run site:build` (`website/README.md`) – never put real personal details into them, tests or docs; use placeholders like "Jane Rider".
